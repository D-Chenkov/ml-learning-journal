# 2026-08-12 (Wednesday, R2) - Project #3 kickoff: 1D-CNN ECG (first trained + evaluated model)

Kicked off Project #3 (ecg-1dcnn). Trained the scaffolded 1D-CNN on the Kaggle MIT-BIH heartbeat CSVs (5 AAMI classes), added inverse-frequency class weights for the imbalance, logged to MLflow, evaluated per class.

**Results (test set, 21,892 beats):**
- Accuracy 0.739, macro-F1 0.536, weighted-F1 0.791.
- Per class (precision / recall / f1): N 0.992 / 0.709 / 0.827; S 0.367 / 0.622 / 0.461; V 0.227 / 0.994 / 0.369; F 0.462 / 0.037 / 0.069; Q 0.949 / 0.958 / 0.954.

**Honest read:**
- Class weighting worked as intended: it broke the "predict everything as N" failure mode. V, S, Q now have high recall (V 0.994, Q 0.958, S 0.622). Without it I would have ~90% accuracy and a useless model.
- But it OVER-corrected toward V. V precision is only 0.227 because the model dumps uncertain beats into V: 4,585 true-N and 154 of 162 true-F beats were predicted V. N recall fell to 0.709 as the cost. Aggressive inverse-frequency weighting does this.
- F (fusion) is the hard class: recall 0.037, almost all fusions misread as V. Clinically sensible - fusion beats are blends of normal + ventricular, so they sit between N and V, and F is the rarest class (162).
- Accuracy is misleading here: accuracy 0.739 vs macro-F1 0.536. Macro-F1 (equal weight per class) is dragged down by F (0.069) and V's poor precision. Judge this model by macro-F1 + the confusion matrix, not accuracy. That 20-point gap IS the imbalance story.

**Confusion matrix highlight (rows=true, cols=pred, order N S V F Q):** true N -> 12,850 N but 4,585 -> V; true F -> 154 of 162 -> V. V is the dumping ground.

**Interview-worthy framing:** the finding is not a headline accuracy number - it is that I surfaced and can explain the imbalance trade-off (weighting fixes majority bias but over-corrects into V) and identified the intrinsically hard class (fusion). That honesty is the point.

**Next levers (Week 7 iteration, not now):** soften the weighting (sqrt-inverse-frequency or effective-number weighting) to curb V over-prediction; train more epochs; try a deeper net / ResNet-style skip connections (Course 3 Module 1); then serve via FastAPI + containerize + finish the model card.
