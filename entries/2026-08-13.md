# 2026-08-13 (Thursday, R2) - Project #3 model iteration: controlled weighting comparison

Made train.py a proper controlled experiment (fixed seed, train/val split, --weighting flag, class weights from the train split only, best-on-val checkpoint, val macro-F1 logged each epoch). Then compared four loss-weighting schemes fairly.

**Controlled comparison (best val macro-F1, seed 42, 10 epochs):**
- class_balanced: 0.862
- none (unweighted): 0.858
- sqrt_inverse: 0.811 (final epoch 0.733 - unstable)
- inverse: 0.752 (final epoch 0.643 - unstable)

**Chosen model (class_balanced) on TEST (touched once):** accuracy 0.889, macro-F1 0.715, weighted-F1 0.913.
Per class (P/R/F1): N 0.989/0.883/0.933; S 0.219/0.806/0.345; V 0.816/0.930/0.869; F 0.310/0.883/0.458; Q 0.983/0.952/0.967.
Confusion (rows true): N sends 1,557 -> S and 262 -> F (the false-alarm cost).

**Honest findings:**
- Class weighting did NOT meaningfully improve macro-F1. Aggressive schemes (inverse, sqrt_inverse) DEGRADED and destabilized it; class_balanced landed within noise of unweighted (0.862 vs 0.858).
- The earlier "inverse-freq helped" belief was an artifact of UNCONTROLLED runs (no seed, tuning on test). In a fair comparison it is the worst scheme.
- Weighting still shifts the precision/recall PROFILE toward rare-class recall (screening-style: catches most arrhythmias, many false alarms), so it is a deliberate trade-off choice, not a macro-F1 win.
- Headline metric is macro-F1 0.715 (test), NOT weighted-F1 0.913 (which is inflated by the 83% N majority). val 0.862 > test 0.715 because val was used for selection / same-distribution as train; test is the honest generalization number.

**Lessons banked:**
- Only class-weight RATIOS matter: a global constant cancels in weighted-mean CrossEntropy, so weights = 1/n and weights = N/n are the SAME objective (this is why old "Run 1" == "Run 3").
- Effective-number (Cui et al.) class weighting: samples overlap as a class grows so information saturates; 1/E_n down-weights the majority softly, unlike the brutal 1/n. beta dials between no-weighting (0) and inverse-freq (1).
- Select on validation, touch test once. Every peek-and-adjust leaks optimism.
- macro-F1 (equal per class) is the honest headline on imbalanced data; weighted-F1 hides minority failures.
- The real levers to push macro-F1 (not loss weighting): more epochs, a deeper net with residual/skip connections, and minority-class data augmentation (Kachuee et al. do all three). Deferred to the PC (heavier compute).
