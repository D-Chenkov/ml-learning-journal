## Module 4 - Preparing Models for Deployment

**Learned:**
- Serialization: save the state_dict (an ordered dict of the layers' learnable tensors + buffers like BatchNorm stats), not the whole model object. torch.save(model) pickles the class + file paths and is brittle to code refactors; state_dict decouples weights from code (reload by instantiating the model then load_state_dict).
- MLflow (already used in Project #1): tracking + model management for the training lifecycle.
- ONNX (Open Neural Network Exchange): a universal, self-contained model graph (operators + weights) that decouples the model from the training framework. Export to it for interoperability (train in PyTorch, deploy anywhere) and optimized, framework-independent inference via ONNX Runtime (CPU/GPU/mobile/edge, usually faster, no PyTorch dependency in prod).
- Pruning: remove parts of the network to shrink/speed it up. Unstructured = zero individual weights (high sparsity, but usually no real speedup without sparse kernels); structured = remove whole filters/channels/neurons (real size + latency wins, coarser). Fine-tune afterward to recover accuracy.
- Quantization: map fp32 -> int8 via a scale + zero-point. Payoffs: ~4x smaller + faster inference + lower memory/energy (great for edge). Risk: precision loss shifts predictions / drops accuracy.
- Dynamic vs static quantization (the dividing line is WHEN activations are quantized): dynamic = weights quantized ahead, activations quantized on the fly at runtime (out of the box, mostly Linear/RNN, not conv); static = both quantized ahead, needs a calibration pass over representative data to fix activation ranges (supports conv, faster at inference, better results).
- QAT (Quantization-Aware Training): simulate quantization during training with fake-quant nodes so the model learns to be robust to rounding; recovers most accuracy lost vs post-training quantization.
- Deployment playbook (assignment - edge/smart-fleet optimization): from the best-quality model, prune (structured) -> retrain to recover -> quantize last (static/QAT for conv edge models) -> checkpoint throughout -> track in MLflow -> export to ONNX -> deploy + measure latency/size/accuracy vs target, iterate. Measure the trade-off at each step.
