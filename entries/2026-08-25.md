**The flywheel (continuous improvement loop):**
1. Initial implementation -> 2. Synthetic data generation -> 3. Fast evaluations -> 4. Real-world data collection -> 5. Classification and analysis -> 6. System improvements -> 7. Production monitoring -> 8. User feedback integration -> 9. Iterate.

**Key takeaways:**
- Get CONCRETE metrics, not vibes. Most teams say a change "seems" better; precision/recall let you actually track advances vs regressions.
- You do not need real data to start: synthetic data can validate viability early, without pigeon-holing on one methodology.
- Leading vs lagging metrics: lagging metrics (validated after the fact) do not cause the change; leading metrics are directly actionable. Optimize the actionable ones.
- Crawl before you walk: nail RETRIEVAL first, with unit-test-style evaluation, before worrying about generation. (Matches my mend: if the answer is wrong, check retrieval first.)
- Strong fundamentals -> then treat RAG as a continuous-improvement system: monitor production questions (classify by topic), spot changing patterns / new needs, talk to users to validate the quantitative findings, prioritize by business impact, run targeted experiments on specific gaps, and feed insights back into synthetic data generation.

**Why it matters:** turns RAG from a vibe-based "seems to work" into a metrics-and-experiments discipline. This is the frame for Project #2's eval step - measure retrieval and generation separately, use the scores to tune chunk size / top-k.
