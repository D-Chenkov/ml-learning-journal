**Learned:**
- 3-layer GCP AI stack: Foundation Models (Gemini, Veo, Nano Banana, Embeddings) -> AI Development (Agent Studio/Garden, Model Garden, Vertex/BQML, notebooks - where ML engineers work) -> AI Applications (Gemini Enterprise App, Notebook - the end-user products). Models -> workbench -> shipped product.
- Foundation models: pretrained on vast data, huge parameter counts (millions -> trillions); "horizontal AI" (broad), then fine-tuned for specific tasks. General (Gemini Pro/Flash) vs specialty (Nano Banana=images, Veo=video, Embeddings).
- Decoding params: temperature reshapes the distribution (low=focused, high=creative); top-k = sample from the k highest-prob tokens (fixed count); top-p/nucleus = smallest set whose cumulative prob >= p (dynamic count). Order: temperature reshapes -> top-k/top-p truncate -> sample. temp=0 = deterministic argmax, so top-k/top-p stop mattering.
- Improve outputs: grounding (goal: answers backed by trusted/current sources) implemented via RAG (retrieve -> inject at inference, no weight change) -> fixes outdated/not-my-data. Model tuning (changes weights) -> fixes style/format/task performance. Try grounding first; tune only if needed.
- Tuning approaches by cost: prompt design (change the input only, no training) < parameter-efficient/adapter e.g. LoRA (FREEZE base, train a small ADDED adapter - not hyperparameters) < full fine-tuning (update ALL weights). Agent Studio supports supervised fine-tuning for well-defined labeled tasks.
- GCP model-build spectrum: pretrained APIs (low-code, common tasks) / AutoML (no-code UI) / BigQuery ML (SQL-native, data already in the warehouse) / Vertex custom training (full control). Data in BQ + SQL team -> BQML.
- ML taxonomy: supervised (labeled) = classification (logistic reg) + regression (linear reg); unsupervised (unlabeled) = clustering (k-means) + association + dimensionality reduction (PCA).
- BigQuery ML: train/eval/predict in SQL, inside the warehouse - no data movement or separate ML stack. Workflow: CREATE MODEL -> ML.EVALUATE -> ML.PREDICT.
- Storage map: unstructured -> Cloud Storage (the data lake); SQL warehouse -> BigQuery; transactional SQL -> Cloud SQL/AlloyDB/Spanner; NoSQL -> Bigtable/Firestore. Hardware: TPUs are matrix-multiply ASICs - far more efficient than CPU/GPU for the dense tensor math in ML.
