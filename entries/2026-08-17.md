**Project #3 train.py upgraded for the PC run** (folded in the training discipline we settled on):
- Early stopping on val macro-F1 (patience 7) so --epochs is a CAP, not a guess. The machine decides the epoch count. Default cap 40; it will usually stop sooner.
- Mixed precision / AMP on CUDA (autocast + GradScaler), auto-disabled on CPU. ~2x GPU speedup, negligible accuracy cost (Course 2 Module 4 material in practice). Toggle with --amp / --no-amp.
- ReduceLROnPlateau scheduler (mode=max on val macro-F1, factor 0.5, patience 3) - halves the LR when validation stalls.
- Bigger default batch (512) + DataLoader num_workers=2 + pin_memory on CUDA to keep the GPU fed.
- Seeded (incl. cuda), train/val split, per-epoch val macro-F1 + lr logged to MLflow, best-on-val checkpoint saved. epochs_run logged too.
- Kept the --weighting flag (none / inverse / sqrt_inverse / class_balanced); class_balanced stays the default.

Recommended PC run command:
`python src/train.py --epochs 40 --batch_size 512 --weighting class_balanced`
