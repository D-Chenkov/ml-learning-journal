# 2026-08-20 (Thursday) - Project #2 kickoff: RAG document Q&A (rag-qa)

Scaffolded Project #2 - a retrieval-augmented Q&A system over my own PDFs, running fully local (Ollama + FAISS, no API keys). Built it structured explicitly around the six-step RAG pipeline (the mend from the LangChain quiz) so the shape is unmistakable.

**Repo (rag-qa), local stack:** Ollama (LLM gemma4:e4b, embeddings nomic-embed-text) + FAISS + LangChain + FastAPI + RAGAS.

**Pipeline, split across two files so the six steps are obvious:**
- ingest.py = steps 1-4 (INGEST, run once): load PDF (PyPDFLoader) -> split (RecursiveCharacterTextSplitter, overlapping chunks) -> embed (OllamaEmbeddings) -> store (FAISS, saved to disk).
- rag.py = steps 5-6 (QUERY, per question): retrieve top-k by similarity -> generate a grounded answer (stuff chunks into the prompt, ChatOllama at temp 0, answer ONLY from context, return sources).
- app/main.py = FastAPI POST /ask (+ /health), lazy-loads the retriever.
- eval_ragas.py = RAGAS eval stub (faithfulness, answer relevancy, context precision/recall) - Friday's task; note RAGAS defaults to OpenAI so it must be pointed at the local models.

**Deliberate TODOs (where the learning is, not scaffolded away):** conversation memory (history-aware chain), MMR / self-query / contextual-compression retrievers, RAGAS eval + tuning chunk size / top-k, Dockerfile + small UI.

**Design notes carried from the courses:** temp 0 for faithful grounded answers; if the model says "I don't know," inspect the retrieved chunks first (usually a retrieval problem, not generation); answers are only as good as retrieval.
