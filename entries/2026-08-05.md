Finished Module 4, which completes Course 2 of the PyTorch for Deep Learning set. Module 4 is about making training fast and efficient: keeping the GPU fed and scaling the training loop. Only Course 3 (transformers, deployment) remains to finish the whole certificate.

**Topics covered (resources-driven):**
- DataLoader performance: keep the GPU from starving on input. Knobs are num_workers, pin_memory, persistent_workers, prefetching. Advanced: NVIDIA DALI (GPU-accelerated decode/augment), WebDataset tar shards for high-throughput streaming, threaded vs process-based loading trade-offs.
- Hardware for deep learning: GPU memory / bandwidth / compute trade-offs (Tim Dettmers guide), finding bottlenecks, and raising GPU utilization via data locality and caching.
- Batch size: the "critical batch size" where bigger batches stop helping; balancing gradient noise, speed, memory, and hardware efficiency.
- Prefetching + pinned memory: page-locked host memory (pin_memory=True) plus non-blocking transfers overlap host-to-device copies with compute so the GPU stays busy. Pinning helps when transfer-bound, wastes RAM otherwise.
- PyTorch Lightning: LightningModule / Trainer abstractions to remove training-loop boilerplate and improve reproducibility; callbacks, loggers, profiler.
- Mixed precision (AMP) + gradient accumulation: autocast + GradScaler speed up training with less memory at minimal stability cost; gradient accumulation simulates a larger batch by summing gradients over several steps before an optimizer step (mind schedulers and clipping).

**Takeaways to carry:** most of this is "don't let data loading or transfers bottleneck the GPU." The practical first-line knobs are num_workers, pin_memory, and AMP; gradient accumulation is the trick for fitting a large effective batch on limited memory.
