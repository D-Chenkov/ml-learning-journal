## GenAI + foundation models
- Generative AI produces multimodal content (text, code, images, speech, video, 3D) from a prompt. Use cases: images/video, summarize meeting notes, research reports, Q&A chatbots.
- Timeline: 2017 Transformer -> 2023 Gemini era -> 2025 Gemini 3 + AI Applications -> 2026 Agent Platform.
- Training on existing content produces a foundation model: large parameter count (millions -> trillions), vast data, high compute. Parameter count roughly indicates capacity to learn complex patterns / store information.
- General models (Gemini Pro/Flash/Flash-Lite) vs specialty models (Nano Banana=images, Veo=video, Embeddings). Foundation models are "horizontal AI" (broad); pretrained THEN fine-tuned for a specific use case.
- Gemini task types: information extraction, information analysis, information seeking (Q&A), content creation.
- Three ways to build multimodal apps: Cloud Console UI (no code, explore/test prompts) / GenAI model API e.g. Gemini API + curl (low code) / SDKs in Python/Java with notebooks (code).

## Prompting + Agent Studio parameters
- Effective prompt design: be direct and specific; use structure/delimiters; iterate from simple; use advanced techniques (RAG); keep basics (no jargon, clear goals). Agent Studio "Help me Write" gives AI-assisted prompt drafting/formatting.
- Model types in Agent Studio: partner models (proprietary, third-party) vs open/open-weight models (trained weights publicly released).
- Decoding parameters:
  - Temperature = randomness. Low = narrow to high-probability tokens (focused); high = include lower-probability/unusual tokens (creative).
  - Top-k = randomly pick from the k most-probable tokens (fixed count). Too permissive a distribution can yield odd responses.
  - Top-p (nucleus) = smallest set of tokens whose cumulative probability >= p, sample from that (dynamic count).

## Grounding vs tuning (the recurring exam distinction)
- Grounding connects the model to trusted external data so answers are verified against the latest info; RAG is the method that implements it (in Agent Studio, ground via Google Search or your own data). Grounding is the ongoing practice of staying current (fresh research/policies).
- Model tuning improves the content GENERATION itself. Three approaches:
  - Prompt design: examples/instructions in natural language; does NOT alter pretrained weights.
  - Parameter-efficient / adapter tuning: adapts a large model to your task by updating a SMALL subset of parameters (added adapter weights).
  - Full fine-tuning: updates ALL parameters; complex tasks, high compute.
- Agent Platform / Agent Studio supports supervised fine-tuning (good for well-defined tasks with labeled data: classification, summarization, extraction, chat). Path: Agent Studio -> Tuning -> Create a tuned model.

## AI agents + Agent Platform
- An AI agent = models (reasoning) + tools (external interaction) + orchestration (coordination), goal-oriented. Analogy: model=brain, tools=hands/senses, orchestration=nervous system. The model can be ONE or MULTIPLE foundation models (ties back to LangChain: route to a specific model/system-prompt as needed).
- Agent build spectrum by code needed:
  - Level 4 solutions (no code): Gemini Enterprise App, Gemini Enterprise for CX.
  - Level 3: Agent Platform / ADK (customizable template, no/low code); ADK = pro code for custom dev.
  - Level 2: low-level orchestration framework (e.g. LangGraph).
  - Level 1: build your own via function calling.
- Gemini Enterprise App: hub to host/build agents; cited answers across all org data formats in one interface; pre-built Google agents + no-code Agent Designer; agents can update tickets, send email, analyze reports. Gemini Notebook can compile sources and build agents. Gemini Enterprise for CX: customer-facing agents (retail).
- Agent Platform pieces: Agent Studio (low-code visual reasoning-loop design + prompt testing); ADK (graph-based logic for networks of sub-agents; agent-to-agent delegation, generative + deterministic patterns); Agent Runtime (deploy/manage/scale in prod; sub-second cold starts, long-running workflows, integrated observability).
