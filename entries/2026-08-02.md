# 2026-08-02 - PyTorch Course 2, Module 2 (TorchVision + transfer learning)

Finished Module 2 of PyTorch Course 2. Computer-vision tooling in PyTorch: TorchVision's transforms, datasets, and pretrained models, then transfer learning / fine-tuning, capped by the FakeFinder graded assignment.

**Learned:**
- TorchVision is the CV companion library: four pieces I care about are transforms, datasets, models, and utils.
- Transforms + preprocessing pipeline: compose steps (resize/crop, ToTensor, Normalize) into one callable. Normalize with the pretrained model's expected stats (ImageNet mean/std) so inputs match what the backbone was trained on.
- Data augmentation (random flips, rotations, crops, color jitter) is applied to the TRAIN set only, never val/test. It expands effective training variety and fights overfitting without changing the evaluation distribution.
- TorchVision datasets: built-in datasets plus the ImageFolder pattern (folder-per-class), fed through a DataLoader for batching/shuffling.
- Pretrained models via torchvision.models with their weights, so I start from features learned on a large dataset instead of random init.
- Transfer learning vs fine-tuning: feature extraction = freeze the backbone and train only a new head; fine-tuning = unfreeze some or all layers and continue training with a small learning rate. Which one depends on how much data I have and how similar my domain is to the pretraining data (small + similar = freeze more; large + different = unfreeze more).
- Utility functions for visualization (grids of images, drawing boxes/masks) to sanity-check inputs and outputs.
- FakeFinder assignment: applied transfer learning to a real classifier end to end (load pretrained, swap head, train, evaluate).

Question-by-question:
- Q1 Normalize on a pretrained model: 5/10. Mixed up ToTensor's [0,1] scaling with Normalize's standardize (subtract mean / divide std). The stats are the PRETRAINING dataset's (ImageNet), and skipping it degrades predictions, not just training speed.
- Q2 augmentation splits: 8/10. Train only; regularization / anti-overfitting; val/test stay deterministic for reproducible metrics.
- Q3 feature extraction vs fine-tuning: 8/10. Freeze backbone + train head vs unfreeze layers + small LR.
- Q4 how to freeze a layer: 3/10 (PRIORITY). It's param.requires_grad = False. torch.no_grad() is for inference, NOT selective freezing. Also set the frozen BatchNorm to .eval() and pass only trainable params to the optimizer.
- Q5 ImageFolder: 9/10. root/class/images; labels from folder names; sorted alphabetically into class_to_idx integer indices.
- Q6 DataLoader: 5/10. Batching + shuffling + parallel workers (num_workers). Extras: pin_memory, drop_last, collate_fn.
- Q7 random head init is fine: 6/10. Because backbone features are already good and the head just learns a cheap linear mapping; must re-init because output shape changed.
- Q8 large + different domain -> fine-tuning (T/F): 8/10. False that feature extraction wins. Domain mismatch means frozen features are a poor fit; large data makes unfreezing safe.
- Q9 Compose order: 6/10. Sequential pipeline; ToTensor before Normalize (Normalize needs a tensor); PIL-based transforms first. (v2 transforms relax this.)
- Q10 make_grid: 8/10. Tile a batch into one image to sanity-check inputs/augmentation/labels straight from the DataLoader.
