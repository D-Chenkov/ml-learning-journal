- **Optuna** is smarter than grid/random search because it *learns from completed trials* to decide what to try next, rather than sampling blindly. The umbrella concept is **Bayesian optimization**: build a probabilistic model of which hyperparameter values tend to produce good scores, then sample new candidates weighted toward the regions that model predicts are promising. Optuna's default sampler is **TPE (Tree-structured Parzen Estimator)**. Grid and random search, by contrast, never use prior trial results at all. (Note for later: Optuna also supports *pruning*, killing an unpromising trial partway through instead of wasting a full training run, a second efficiency lever beyond smart sampling. Not covered in this module; flagging as a follow-up.)
- **Efficiency vs. performance tradeoff**: a model's quality (accuracy/F1) isn't the only axis, you also track efficiency metrics, and sometimes deliberately accept a less accurate model to win on efficiency. Standard efficiency metrics: inference latency (time per prediction), throughput (predictions/sec), model size (MB / parameter count), and compute footprint (FLOPs / memory). Canonical case for trading accuracy away: edge/resource-constrained devices (phones, embedded hardware, a microcontroller-class robot build) where a large accurate model won't fit or won't respond fast enough. A slightly-less-accurate model that runs in real time beats a more accurate one that can't run on the hardware at all. Real-time face recognition is another instance (speed matters as much as raw accuracy).
- Flexible Architecture Design: building models so architecture choices (layer sizes, counts, etc.) are parameterized rather than hard-coded, which is what makes them tunable by a tool like Optuna in the first place, the search space is defined over those parameters.
