## Slammers! (Unity game for YouTube Playables)
A nostalgic 90s Tazos/Pogs 3D physics battle game, built specifically for the YouTube Playables ecosystem. Part of a plan to submit 3 games to YouTube Playables - for fun and possible monetization, explicitly a side-track from the ML-engineer path, not a replacement for it.

**Concept:** aim, charge, and slam a collectible slammer disk onto scattered opponent tazos to flip them face-up; best-of-3 rounds vs an adaptive AI; schoolyard arenas with physics-altering floor grooves and ricochet bumpers; collection + stat upgrades; ad-monetization hooks (interstitials between rounds, a rewarded-ad "Metallic Mega Slammer").

**Tech stack:** Unity 6 (6000.5.10f1), Universal Render Pipeline, New Input System, WebGL/HTML5 with a strict <30MB payload + 60fps target for Playables. Local persistence via PlayerPrefs.

**Architecture already scaffolded (Assets/Scripts/):** GameManager (match state machine: Toss -> PlayerTurn -> AITurn -> ResolvingPhysics -> RoundEnd -> MatchEnd), RoundManager (best-of-3, timer, scoring), TazoDisk (rigidbody physics + edge-torque flip detection via face-normal vs up-vector), SlammerController (drag aim, trajectory arc, charge power-ring, slam force), FloorGroove (physics nudge zones), SlammerAI (Casual / Medium / Aggressive-ricochet presets), MatchHUD, CollectionUI, AdManager, SoundManager, plus editor/test tooling. Detailed design doc at Assets/Plans/slammers-core-gameplay.md.

**What I picked up quickly:** Unity rigidbody physics (torque/flip detection, resting-state settling), URP performance budgeting for a tight WebGL payload, the New Input System, game state machines, and YouTube Playables' ad-monetization flow.
